# 部署手册

火情监控的 Windows 部署说明。申报材料中的软件名称拟用「校园智能火情预警与辅助决策系统 V2.0」。程序界面和本仓库仍称火情监控。

本文按当前 main 的程序编写。模型权重不在 Git 仓库里。

## 1. 运行环境

需要 64 位 Windows 10 或 Windows 11，以及：

- Docker Desktop。`compose.yaml` 只启动 MySQL 8.4 和 MinIO。
- Python 3.11、3.12 或 3.13。脚本发现缺失时用 winget 安装 3.12。
- Node.js，用来构建前端。已经有 `apps/web/dist/index.html` 时可以不装 Node。
- FFmpeg，供 USB 摄像头推流。
- MediaMTX。脚本发现命令不存在时下载 1.15.3 的 Windows 64 位压缩包，解压到 `.tools/mediamtx`。压缩包 SHA-256 为 `2971f7b509baa89f26ca6f099b6a6896039be19edd24bf982b65199826c59f04`。
- 浏览器。构建后的页面和后端同源，默认地址是 `http://127.0.0.1:8080`。

实况检测还要把微调权重放到 `models/yolo26s-ft-2026-11-04/best.pt`。没有这个文件时，演示模式仍可打开；加载模型做实况检测会失败。交接记录里的 SHA-256 见发布说明，部署前用本机文件再算一次。

## 2. 一键安装和启动

在仓库根目录执行：

```text
scripts\windows\install-and-start.bat
```

也可以分开执行：

```text
powershell -ExecutionPolicy Bypass -File scripts\windows\install.ps1
powershell -ExecutionPolicy Bypass -File scripts\windows\start.ps1
```

`install.ps1` 可以重复运行。它依次做这些事，任一步失败就停止：

1. 检查 Docker。没有就退出，并说明要先安装、打开 Docker Desktop。
2. 检查 Python 版本。没有合适的解释器就安装 Python 3.12，再在仓库里创建 `.venv`。已有 `.venv` 但版本不是 3.11 到 3.13 时退出，不自动删除。
3. 用虚拟环境安装 `apps/inference` 和 `apps/server[detect]`。
4. 有 Node 就在 `apps/web` 执行 `npm ci` 和 `npm run build`。没有 Node、但已经有构建结果时，直接使用该结果。两样都没有就安装 Node 再构建。
5. 检查 FFmpeg，没有就用 winget 安装。
6. 检查 MediaMTX。下载的压缩包若校验不一致就退出。`config.json` 里的 `mediamtx_path` 仍是 `mediamtx`、且命令不在 PATH 时，写成 `.tools\mediamtx\mediamtx.exe`。已经改过的路径保持不动。
7. 没有 `config.json` 时从 `config.example.json` 复制。已有文件不覆盖。脚本不写入密钥。

`start.ps1` 接着启动：

1. 要求 `config.json`、`.venv` 和前端构建都已经存在。
2. 执行 `docker compose up -d`，并等待本机 3306 和 9000 端口。
3. 若后端或 MediaMTX 已由这些脚本启动，则退出，并要求先运行 `stop.ps1`。
4. 设置 `FIRE_WEB_DIST` 为 `apps/web/dist`，执行 `python -m fire_monitoring`。
5. 按数据库中的摄像头生成 `runtime/mediamtx.yml`，启动 MediaMTX，并对 USB 摄像头启动 FFmpeg。
6. 打开浏览器。

开发时仍可在仓库根目录执行 `python -m fire_monitoring`，并在 `apps/web` 执行 `npm run dev`。开发服务器地址是 `http://127.0.0.1:5173`，它把 `/api` 代理到 `config.json` 里的后端。

## 3. 配置

`config.json` 含口令，不要提交，也不要写进文档。未知字段会被拒绝。

示例中的数据库密码、MinIO 密钥和 `jwt_secret` 是占位值，与 `compose.yaml` 的本机默认值一致，只适合这台电脑。脚本发现这些占位文本会提示，但不会替换。换机器或交给别人使用之前，改成自己的值。

千问和短信默认关闭，密钥留空。启用时再填写 `llm.api_key` 和短信的访问密钥。水泵、报警节点默认关闭；`enabled` 为 true 时必须填写串口，否则程序拒绝启动。

`auth.users` 只在数据库还没有账号时用来创建初始用户。示例账号是 `admin` / `123456`（管理员）和 `duty` / `123456`（值班员）。正式使用前在用户管理中修改密码。

其余字段的含义见仓库 README。管理员可以在「系统配置」里修改非密钥项，保存后需要重启后端。密钥不返回到页面，也不能在页面上修改。

## 4. 看到四路实况

一键启动只保证服务和空的监控页。四路实况还要有摄像头：

1. 用管理员登录。
2. 在教室管理中新建教室。场景按房间选择。配电间、实验室等场景会进入灭火规则。
3. 在摄像头管理中添加摄像头。USB 填写 DirectShow 设备名，网络摄像头填写 RTSP 地址。教室最多绑定 4 路。
4. 在教室详情中把摄像头绑到槽位。
5. 重新运行 `scripts\windows\start-streams.ps1`。
6. 打开监控，选择该教室。四宫格通过 WebRTC（WHEP）播放 MediaMTX 的画面。

没有摄像头、或者还没执行第 5 步时，看不到四路实况。这一步依赖现场设备。本仓库没有在一台干净的 Windows 上从零执行过 `install-and-start.bat`，由操作者按本节完成。

标定、平面图、告警处置和灭火见《用户手册》。

## 5. 演示模式

没有摄像头和 ESP32 时：

```text
scripts\windows\start-demo.bat
```

演示模式仍然使用 MySQL 和 MinIO。脚本根据当前 `config.json` 写出 `runtime/demo.config.json`，只改这份副本：打开演示、硬件用 `sim`、检测用 `replay`，并关闭水泵和报警节点串口。原来的 `config.json` 不改。不启动 MediaMTX，不打开串口。

材料在 `data/demo/synthetic-classroom`。`SYNTHETIC.txt` 写明这是虚拟教室、程序火焰和手写的千问响应，不是现场录像，也不是模型在线输出。登录后监控页改为「画面回放」。数据大屏和数字孪生只在演示模式出现。管理员可播放「完整灭火」「带电火灾禁水」「有人避让」。

## 6. 停止与回滚

停止脚本拉起的进程：

```text
powershell -ExecutionPolicy Bypass -File scripts\windows\stop.ps1
docker compose stop
```

`stop.ps1` 不停止 Docker。

P9 改动之前的 main 是 `1a80bbc`。标签 `p8-done` 和 `before-p9` 都指向这个提交。

合并之后若要撤回 P9，对合并提交执行 `git revert -m 1`，另开回滚 PR。不要强推 `main`。

只查看 P9 之前的程序时，可以 `git checkout before-p9`。这不改写 `main`。

## 7. 本仓库已核对的范围

干净 Windows 上的从零安装没有在本环境执行。
