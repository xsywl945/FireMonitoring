# 智能火灾监控系统第一阶段计划：火焰与烟雾检测模型

版本：v1.0  
日期：2026-07-16  
阶段周期：2026-07-16 至 2026-08-25（预留 2026-08-26 至 2026-08-31 作为缓冲）

## 1. 阶段目标与边界

本阶段只解决“从单帧画面中定位火焰与烟雾”的基础感知问题，训练一个可复现、可部署、可供后续时序融合和双摄决策调用的 YOLO 检测器。

本阶段不直接训练双摄特征融合网络，也不让多模态大模型代替目标检测。两路摄像头先共享同一套检测权重，分别输出标准化检测结果；后续阶段再基于单摄时间序列与双摄决策进行融合。这样可以先把数据、检测器和评测基线做扎实，避免把多视角、时序和语义研判的误差混在一起。

阶段结束时应交付：

1. 经过审计、去重和分组划分的 `fire/smoke` 数据集清单及数据卡；
2. YOLO11s 可复现基线与 YOLO26s 候选模型；
3. 在公开测试集、跨数据集测试集和教室/实验室负样本视频上的完整评测；
4. 最佳 PyTorch 权重、ONNX 模型、推理配置和训练日志；
5. 错误案例库，以及下一阶段时序融合和双摄融合所需的检测输出接口。

## 2. 与项目计划书和本地论文的衔接

项目申请书将系统划分为感知层、分析层、决策层和执行层，并把“火灾识别模型设计与训练”安排为首个核心研发任务。暑期计划进一步要求先使用公开数据完成 YOLO 预训练，再用校园场景样本降低误报。本计划据此把第一阶段拆成“公开数据基线 - 目标场景适配 - 视频化验收”三段。

本地论文给出的直接启示如下：

- 《DetectiumFire》说明，数据多样性、困难负样本和跨数据集泛化比单纯堆积图片数量更重要；它还提供室内受控火焰、失控火焰、风险等级和文本描述，可在后续语义研判中复用。
- 《Indoor fire and smoke detection based on optimized YOLOv5》公开了 IFireSmoke 室内双类检测集，可用于弥补大规模公开数据偏室外的问题；但论文内的随机图像划分仍需额外做场景/来源去重检查。
- 《SmokeBench》表明，多模态大模型对小体积、早期烟雾的精确定位仍不可靠，因此不能把基础检测器的漏检交给大模型兜底。
- 时空残差网络论文使用连续 16 帧建模，并指出小火焰、低对比烟雾、蒸汽、雾和粉尘是主要失败情形。本阶段应保留视频/场景分组信息，为后续时序模块提供无泄漏的数据接口。
- 《CaMuViD》适合启发后续多视角研究，但它面向同步重叠视野的行人检测，不能直接当作火焰/烟雾双摄方案。第一版先做决策级双摄融合，不在本阶段改造其特征投影网络。

## 3. 数据集选择

### 3.1 主训练集：FASDD_CV

优先使用 FASDD 的计算机视觉子集，而不是遥感子集。FASDD 全集有 101,087 张样本，其中 FASDD_CV 有 95,314 张；全数据包含 59,177 张正样本、41,910 张负样本，以及 82,666 个火焰实例和 57,742 个烟雾实例。其图像覆盖室内/室外、昼/夜、近/远距离、监控/无人机/卫星等条件，提供 YOLO、COCO、VOC、TDML 四种标注格式。第一阶段只取 FASDD_CV，以减少遥感图像与教室、实验室监控之间的域偏差。

官方入口：

- 项目页：https://github.com/openrsgis/FASDD
- 数据 DOI：https://doi.org/10.57760/sciencedb.j00104.00103
- 论文：https://doi.org/10.1080/10095020.2024.2347922

### 3.2 外部测试与困难负样本：D-Fire

D-Fire 有 21,527 张图像，其中仅火焰 1,164 张、仅烟雾 5,867 张、火焰和烟雾同时出现 4,658 张、无火无烟 9,838 张；标注包括 14,692 个火焰框和 11,865 个烟雾框。其大量空标注图像适合检查误报。

第一轮中不把 D-Fire 全部并入训练，而是先按官方划分保留测试集，测量 FASDD_CV 训练模型的跨数据集性能。确认基线后，仅将 D-Fire 训练部分中的困难负样本和互补正样本加入第二轮训练，测试部分始终冻结。

官方入口：https://github.com/gaia-solutions-on-demand/DFireDataset

### 3.3 室内专项补充：IFireSmoke

IFireSmoke 是本地论文《Indoor fire and smoke detection based on optimized YOLOv5》配套的公开数据集，含 5,000 张室内图像和 5,931 个实例，其中火焰实例 3,121 个、烟雾实例 2,810 个；官方划分为 80% 训练、10% 验证、10% 测试。数据由本地拍摄、网络/CCTV 图像和合成图像组成，比例约为 60:40，并采用 YOLO 标注。

它的场景与本项目更接近，适合作为 FASDD_CV 的室内域补充。应冻结其官方测试部分，并先检查训练、验证、测试间是否存在相同视频、相同房间或近重复图像。由于它只有 92.3MB，可优先下载审计。

官方入口：https://huggingface.co/datasets/shahriar-5/IFireSmoke

论文：https://doi.org/10.1371/journal.pone.0322052

### 3.4 补充数据：DetectiumFire（有条件使用）

DetectiumFire 包含约 14.5k 真实图像、2.5k 真实视频和 8k 合成图像；真实图像中约 7k 为火焰图像、7k 为非火图像，并包含 3,374 张室内火焰图像以及受控/失控、燃烧物、环境、风险等级等文本信息。

它适合补充蜡烛、打火机、火柴、炉火、电气火灾、厨房火灾等室内火焰形态，也适合后续多模态语义研判。但在并入双类检测训练前必须先检查下载包中的类别表和每张图像的标注覆盖范围。如果烟雾没有完整标注，则不能把含烟图像作为 `fire/smoke` 双类训练数据，否则会把真实烟雾当作背景。第一阶段将其列为可选的“火焰专项补充集”，而不是主烟雾数据集。

论文与数据入口：https://arxiv.org/abs/2511.02495

### 3.5 必须自建的数据

公开数据无法代表太原理工大学教室和实验室的摄像头高度、压缩码率、光照及干扰物。应尽快收集：

- 2,000 至 5,000 张目标域困难负样本，覆盖投影屏、红色海报、夕阳、灯光反射、窗外云雾、空调蒸汽、烧水蒸汽、粉尘、焊接/电弧、人员遮挡和低照度噪声；
- 至少 10 至 20 小时无火视频，用于测量“每摄像头小时误报数”；
- 经学校、指导教师和场地管理方批准后采集的少量安全可控正样本；严禁为了采集数据自行在教室或实验室制造明火或烟雾；
- 后续双摄验证用的同步成对视频，保存 `camera_id`、时间戳和场景编号。

目标域数据不得与训练集来自同一段连续视频；验收视频应在模型和阈值冻结前隔离。

## 4. 数据工程规范

### 4.1 统一类别和目录

统一为两类：

```text
0: fire
1: smoke
```

对每个样本生成清单字段：

```text
sample_id, source_dataset, source_url, license, scene_id, video_id,
camera_id, timestamp, image_path, label_path, width, height,
has_fire, has_smoke, is_negative, split
```

### 4.2 质量审计

下载后先执行审计，不直接开训：

1. 检查损坏图片、越界框、零面积框、类别编号、空标注文件和图像/标签缺失；
2. 随机人工复核每个来源至少 300 张，并重点复核小烟雾、半透明烟雾、遮挡火焰和负样本；
3. 用感知哈希和视觉特征做数据集内及跨数据集近重复检查；
4. 对来自视频的帧保留 `video_id`，不得把同一视频的相邻帧分到训练、验证和测试三侧；
5. 统计每类框数量、框面积分布、长宽比、正负样本比例、场景和来源比例；
6. 对有争议的烟雾框保留审核状态，不把边界极不确定的标注直接作为高权重训练样本。

### 4.3 划分原则

建立两套评测协议：

- 论文可比协议：保留公开数据官方划分，报告公开测试集结果；
- 项目可信协议：按 `source_dataset + scene_id + video_id` 分组划分，避免相邻视频帧泄漏，并保留完全独立的校园视频测试集。

建议项目划分比例为训练 70%、验证 15%、内部测试 15%，但分组完整性优先于精确比例。D-Fire 官方测试集和校园验收集在所有调参结束前保持冻结。

## 5. 模型与实验设计

### 5.1 模型选择

第一阶段采用两个模型，不立即修改网络结构：

- YOLO11s：复现基线。生态成熟，本地 DetectiumFire 论文也采用 YOLO11m 做数据集比较，便于说明实验来源；
- YOLO26s：当前部署候选。官方版本支持端到端、默认无需 NMS 的推理路径，适合后续导出和实时部署。

暂不把 YOLOv13 改进网络作为第一条训练线。应先固定数据和评测，之后再把 YOLOv13、多尺度注意力、P2 小目标头等作为消融实验，否则无法判断提升来自数据、训练策略还是结构改动。

双摄像头使用同一个检测模型权重。单摄输出格式固定为：

```json
{
  "camera_id": "cam_a",
  "timestamp_ms": 0,
  "detections": [
    {"class": "smoke", "confidence": 0.83, "bbox_xyxy": [0, 0, 0, 0]}
  ]
}
```

### 5.2 训练顺序

至少完成以下四组实验：

| 编号 | 模型 | 训练数据 | 用途 |
|---|---|---|---|
| A | YOLO11s | FASDD_CV | 建立最小可复现基线 |
| B | YOLO11s | FASDD_CV + IFireSmoke 训练部分 | 验证室内专项数据的域适配效果 |
| C | YOLO11s | B + D-Fire 训练部分 | 验证困难负样本和数据互补效果 |
| D | YOLO26s | A-C 中最佳数据版本 | 比较当前部署模型 |
| E | 最佳模型 | 最佳公开数据 + 校园训练负样本 | 目标场景适配与最终候选 |

DetectiumFire 只有在类别覆盖核验通过后，才新增“F：室内火焰补充”实验；不能直接覆盖 A-E 基线。

### 5.3 初始训练配置

初始配置以可复现为主：

- 使用 COCO 预训练权重；
- 输入尺寸先用 640，训练 100 个 epoch，早停耐心值 20；
- 单卡混合精度训练，batch 使用显存自动探测后的稳定值；
- 固定随机种子并保存完整配置、软件版本和 Git 提交号；
- 首先做 10% 数据、10 个 epoch 的冒烟测试，验证标签、显存、速度和断点恢复；
- 不在第一轮使用过强的数据增强。烟雾是半透明、形态不规则目标，过强 Mosaic、MixUp 或不符合物理规律的复制粘贴可能制造伪特征；
- 若错误分析确认主要问题是远距离小烟雾，再把输入尺寸提高到 960，并单独比较 P2 小目标头，不能在没有基线时同时更改多项配置。

完整训练轮数根据验证集曲线决定，不把“100 epoch”当作固定性能保证。

## 6. 评测与验收

### 6.1 必报指标

图像级检测指标：

- `AP50`、`AP50-95`、Precision、Recall、F1；
- 分别报告 `fire` 与 `smoke`，不得只报两类平均值；
- 按小/中/大目标、昼/夜、室内/室外和数据来源分组报告；
- 公开同域测试、D-Fire 跨域测试、校园目标域测试分别报告，不能混成一个数字。

系统级安全指标：

- 事件召回率：每个真实火情片段是否至少被发现一次；
- 首次可见火焰/烟雾到首次报警的时间；
- 每摄像头小时误报事件数，而不是只统计独立帧误报率；
- 对蒸汽、雾、粉尘、强光、投影屏和受控火焰分别建立混淆统计；
- 两路摄像头分别报告性能，为后续双摄融合提供可靠度先验。

### 6.2 第一阶段验收门槛

以下是工程门槛，不是对真实消防安全能力的认证：

- 最佳模型在校园隔离测试集上，火焰与烟雾的事件召回率均不低于 90%；
- 经简单的 `3/5` 帧持续性规则后，无火校园视频误报不高于 0.2 次/摄像头小时；
- 在 AutoDL 训练环境和目标部署环境中可稳定复现推理，连续视频测试无内存增长；
- 模型输出、阈值、预处理和类别映射全部版本化；
- 若未达到门槛，必须根据错误案例明确归因于数据覆盖、标签质量、尺度、域偏移或模型结构，不能只继续盲目增加 epoch。

在尚未完成受控现场测试、长期误报测试和传统消防传感器联动前，本模型只能作为研究原型和辅助预警模块，不能宣称替代合规消防报警设备。

## 7. AutoDL 实施方案

### 7.1 推荐实例

首选单张 RTX 4090 24GB、至少 64GB 内存和至少 100GB 可用数据盘。YOLO11s/YOLO26s 在 640 或 960 分辨率下不需要 A100；若 5090 32GB 的实时价格接近，也可选择 5090 以获得更大 batch，但所有对比实验必须使用相同硬件或记录实际配置。

建议从 AutoDL 官方 PyTorch 镜像起步，固定 Python、PyTorch、Ultralytics 和 CUDA 相关版本。一般不需要在镜像中另装系统 CUDA；应以 PyTorch 实际绑定的 CUDA 版本为准，而不是只看 `nvidia-smi` 显示的最高支持版本。

### 7.2 存储与上传

AutoDL 每个地区的免费网盘空间为 20GB，完整 FASDD_CV、缓存和实验输出很可能超过该容量。因此建议：

1. 原始压缩包和重要权重保存在 AutoDL 网盘或第三方网盘；
2. 实例开机后把数据复制到 `/root/autodl-tmp` 数据盘再训练；
3. 不直接从 `/root/autodl-nas` 持续读取训练数据，官方文档明确指出网盘性能低于数据盘；
4. `best.pt`、`last.pt`、配置、日志和指标表定时同步回持久存储；
5. 做完实验立即关机，避免实例处于“运行中”持续计费。

### 7.3 Clash TUN 模式的影响

本机 Clash TUN 只代理本机网络，不会自动代理 AutoDL 远程实例。AutoDL 上的 `127.0.0.1:7890` 指向远程实例自身，不是本机 Clash；不要直接把远程 `HTTP_PROXY/HTTPS_PROXY` 设置为本机回环地址。

推荐的数据传输路径是：

1. 在本机通过 Clash TUN 下载 Kaggle、GitHub 或论文附件；
2. 本机完成校验和计算并保存下载来源、时间和许可文件；
3. 将数据按来源分别打包后上传到 AutoDL 公网网盘、阿里云盘或对象存储；
4. AutoDL 实例从网盘拉取到数据盘。

只有在确实需要让 AutoDL 访问本地代理时，才考虑经过认证和加密的反向隧道；第一阶段没有必要增加这项网络和安全复杂度。

6. 冒烟训练通过后启动实验 A，同时开始收集校园无火困难视频；
7. 每次实验只改变一个主要因素，并把配置、权重、指标和错误图全部归档。
